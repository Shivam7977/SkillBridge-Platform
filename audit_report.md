# Resume Edit behavior — Phase 1 static audit

## Scope and confirmed facts from code

- Reviewed `templates/resume_builder.html` (2,261 lines), `templates/resume_pdf.html` (1,565 lines), `routes/resume_portfolio.py`, and `services/utils.py`. The edit panel and builder JavaScript were read in line-numbered chunks (`resume_builder.html:900-1005`, `1714-2257`), and template block starts, section labels, and class signatures were extracted for all 19 builder blocks (`1077-1707`). I did not read every CSS declaration verbatim: `resume_builder.html:1-332` and `333-795` were scanned for template/selectors, not line-by-line. In `resume_pdf.html`, I read lines `1-120`, extracted all `#t1`–`#t19` block starts (`797-1430`), and located `#t19`; I did not read every other PDF-template line verbatim (`121-796`, `797-1429`, `1431-1565`). These skipped portions do not contain the builder's Edit JavaScript, but a full visual/PDF markup review was outside the static edit-hook trace. No existing application, route, template, or static source files were changed. No Python code was executed.
- The builder has **19** chooser cards (`resume_builder.html:1024-1042`) and **19** preview blocks `#t1` through `#t19` (`resume_builder.html:1077-1707`). The designs are separate DOM blocks, selected by CSS class `.rt.on` (`resume_builder.html:1715-1721`), with per-template CSS themes (`resume_builder.html:333-795`). Template 2 is the exceptional markup structure: it uses `t19-*` classes (`resume_builder.html:1107-1203`); template 19 has ordinary `.sec/.st/.nm/.role/.pj` hooks (`resume_builder.html:1677-1707`).
- Template 19 is named “Startup Founder” in the builder chooser (`resume_builder.html:1042`) and has its own builder preview/CSS (`resume_builder.html:735-760`, `1677-1707`). `templates/resume_pdf.html` also has 19 preview blocks `#t1`–`#t19` (`797-1430`), but `/resume_pdf` clamps all `t > 18` to 1 (`routes/resume_portfolio.py:82-100`), so `/resume_pdf?t=19` renders template 1. `TEMPLATE_NAMES` has only keys 1–18 (`services/utils.py:47-52`); moreover, names after #1 are offset from current builder cards because Clean ATS was inserted as builder #2 without corresponding map shifts. The precise route/display name for #19 is therefore not currently addressable through that endpoint.
- Routes are read-only with respect to editor changes: `/resume_builder` loads profile/project data and renders the builder (`routes/resume_portfolio.py:46-79`); `/resume_pdf` loads the user and completed projects from the database, then renders PDF template data (`routes/resume_portfolio.py:82-100`). There is no resume edit/save route in that module. The editor explicitly says changes apply to preview only and reset when leaving (`resume_builder.html:930-931`). Browser “Download PDF” builds a standalone document from the edited active DOM (`resume_builder.html:1733-1737`, `1815-1821`); it does not call `/resume_pdf`.
- Static literal-ID inventory from PowerShell text scanning: **50 occurrences / 50 distinct IDs, zero duplicate literal IDs**. Literal `getElementById()` targets are present in the markup. Dynamic IDs (`'t' + n`, `'ep-proj-title-' + i`, `'ep-proj-desc-' + i`) were reviewed separately. Per-template repeated Jinja loop output uses classes, not repeated IDs; the project editor IDs contain `loop.index0` (`resume_builder.html:993-1000`).
- This static review cannot confirm browser execution, rendered output for a particular user's data, or console behavior. `tools/audit_resume_templates.py` has not been run because Python execution was expressly disallowed.

## Edit mechanism end to end

1. The “Edit Content” button uses inline `onclick="toggleEditPanel()"` (`resume_builder.html:903-905`). It opens/closes the fixed `#edit-panel` side panel (`resume_builder.html:917`, `1950-1960`). This is a form editor, not per-section pencil buttons or `contenteditable`; the panel has inputs for name, title, email, location, LinkedIn/GitHub, about, goal, known/learning skills, experience years, education entries, work experience entries, and project title/description (`resume_builder.html:933-1000`). It has **no certificate editor**.
2. Panel fields call `liveUpdate()` inline on input. DOMContentLoaded calls `populatePanel()`, renders editable experience/education lists, and immediately calls `liveUpdate()` (`resume_builder.html:1861-1947`). The list fields also mutate `epExpEntries`/`epEduEntries` and call `liveUpdate()` (`resume_builder.html:1871-1908`).
3. `liveUpdate()` finds the active preview by `document.getElementById('t' + cur)` (`resume_builder.html:1967-1983`). It updates name with `.nm,.h-name`, role with `.role,.h-role`, summary paragraphs with `p.about`, then scans `.sec` sections by `.st` label for summary, goal, skills, and learning (`resume_builder.html:1985-2025`). It rewrites contact email/LinkedIn/GitHub/location through icon/class selectors (`resume_builder.html:2027-2043`), has a special `cur === 2` path for Clean ATS (`resume_builder.html:2046-2103`), updates project cards through `.pj/.pt/.pd` (`resume_builder.html:2105-2114`), and rebuilds sections with exact “Experience” / “Education” labels (`resume_builder.html:2116-2154`).
4. Template switching (`sw`) changes `.rt.on`, updates `cur`, then reruns `liveUpdate()` (`resume_builder.html:1715-1732`). It does not replace a template's `innerHTML`, so template preview listeners are not lost on switching. The mobile chooser clones only chooser cards (`resume_builder.html:2225-2237`), not preview content.
5. “Download PDF” in this editor is a local print window created from the current preview's `outerHTML`, so current live edits are included (`resume_builder.html:1733-1737`, `1815-1822`). `/resume_pdf` separately queries persisted database data and applies its own template number clamp (`routes/resume_portfolio.py:82-100`); preview edits do not reach that server-rendered PDF or persist to the DB.

## JavaScript execution review

The Edit-related application script occupies `1714-2257` (the file also has a separate Tailwind config script at `13-30`). No syntax-stopping error is evident by static inspection. Required panel IDs are present (`935-998`), the global data object is initialized before `DOMContentLoaded` (`1842-1859` before `1943-1948`), and `sw()` guards mobile-list access and calls `liveUpdate()` after setting `cur` (`1715-1732`). The failures identified here are selector/label coverage gaps or absent editor controls, not proven JavaScript exceptions. This is not a substitute for browser console observation.

## Ranked root-cause hypotheses (with browser confirmation steps)

These are hypotheses about the user's reported symptom, grounded in confirmed source mismatches. Browser testing is still needed to confirm the visible result for the account's data.

1. **Shared `liveUpdate()` targets a common class/label vocabulary that several designs do not follow.** Evidence: `liveUpdate()` selector logic at `resume_builder.html:1995-2025`, `2105-2114`, `2157-2169`; #6 “Tech Stack” is bars (`1309`), #9 calls its goal “Design Vision” (`1381`), #11 skills “Competencies” (`1444`), #15 goal “What I Seek” and skills “Disciplines” (`1570`, `1575`). **Test expected-working:** select #1 Classic Tech, change Known Skills and Career Goal. **Test expected-failing:** select #6 Data Scientist, change Known Skills; bars should remain unchanged. Also test #15 Freelancer, change About Me and Career Goal; “What I Seek” can mirror the About Me text.
2. **Clean ATS (#2) is a partial adapter to a bespoke DOM, leaving project and learning edits without write-back.** Evidence: different `t19-*` markup (`1107-1203`), special code branch covers summary/contact/known skills/education/experience (`2046-2103`), while project updater only selects `.pj` (`2105-2114`) and learning is not changed in the special branch. **Test expected-working:** #2 change Full Name or Summary. **Test expected-failing:** #2 change project title or Learning Skills; preview has no corresponding `t19-*` update.
3. **Years of Experience is a dead editor field.** Evidence: field is populated (`1930`) and calls `liveUpdate()` (`974-975`), but `liveUpdate()` reads no `ep-exp` value (`1968-2155`); the original `ORIG.exp` is never referenced after populate (`1855`). **Test expected-working:** #1 change Full Name. **Test expected-failing:** #6 change Years of Experience; its “Yrs Exp” stat should stay unchanged (`1292`). This applies also to displayed years in #8, #10, and #18.
4. **No certificate edit control exists.** Evidence: panel fields run from identity through projects with no certificate input (`933-1000`); `liveUpdate()` has no certificate branch. **Test expected-working:** #1 project title. **Test expected-failing:** #1 certificate name; there is no panel field to change it.
5. **Template numbering drift makes the builder and PDF route disagree on template identity and count.** Evidence: chooser #2 Clean ATS and #3 Minimal Pro (`1025-1026`), `TEMPLATE_NAMES` has 18 old labels (`services/utils.py:47-52`), route clamps >18 to 1 (`routes/resume_portfolio.py:86-90`), and PDF template does contain `#t19` (`templates/resume_pdf.html:1430`). **Test expected-working:** `/resume_pdf?t=1` loads block #1. **Test expected-failing:** `/resume_pdf?t=19` is normalized to #1 by source code. The `TEMPLATE_NAMES` name for #2 also says Minimal Pro although builder #2 is Clean ATS.

## Proposed minimal fix location (not applied)

If approved after this audit, start with a small targeted change in the shared `liveUpdate()` in `templates/resume_builder.html` (`1967-2169`): add selector/section adapters for the exceptional design hooks and semantic labels, plus write back the `ep-exp` field to the applicable displayed stats. Focus on #2 projects/learning, #6 skill bars, and unsupported labels such as #9 “Design Vision”, #11 “Competencies”, and #15 “What I Seek” / “Disciplines”; do not edit 19 template copies. Certificate editing requires an explicit new control/data path and is a separate scope choice. Template numbering (`TEMPLATE_NAMES` and the PDF clamp) is a separate discrepancy; no change is recommended until you decide whether the target is 18 or 19.
